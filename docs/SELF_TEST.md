## 0. 本轮做了什么（轮次 6 反馈闭环）

| 你的反馈 | 本轮处理 |
|---|---|
| 1. 主题色只是按键色，我要的是**整体界面主题色**，如深色背景 + 青瓷按键 | 每套配色现在带**浅色 / 深色两份完整色板**：背景、卡片、5 级容器色、正文、次要文字、描边全部随配色走。另加**明暗模式**（跟随系统 / 浅色 / 深色），默认跟随系统。设置页色卡改成**双层预览**（外圈=背景色、内圈=按键色），一眼看出实际搭配 |
| 2. 首页底部「设置与白名单 / 关于与许可」**折行**，三个二级页 UI 不一致 | 底部三入口改为**整行可点的列表**（不折行、点区更大）；页面框架统一为唯一 `ScreenFrame`（固定标题栏 + 返回 + 常驻提示 + 可滚动内容区），设置 / 关于 / 诊断 / Shizuku 四页观感一致 |
| 3. 清理目录时希望**能点选查看实际手机目录路径** | 结果页每条**整行可点**，弹出「实际路径 / 文件位置」：完整路径（可长按复制）+ **当场重新探测**（还在不在、几个子项）+ 删除模式 + 「在文件管理器中打开」。深度确认页的条目也能点 |
| 4. 增加**超过 1 个月的大文件索引**并给出路径 | 新增「**超过 30 天的大文件**」分组：体积 >= 50 MB 且最后修改 >= 30 天，显示大小 / 最后修改 / 已 N 天未改动，点开即完整路径。**只索引、永不删除**，也不可勾选 |

### 三条要留意的设计取舍

1. **语义红不随主题变**：禁止 / 不可恢复永远用红色（浅色 `#C62828`、深色提亮为 `#FF6B6B`），
   换配色不会把「危险」变淡。
2. **大文件索引去重**：Download 目录与 `.apk` 已经有单独分组，索引里排除它们，
   同一个文件只出现一次，不会算两遍、也不会让你以为要清两次。
3. **索引不额外扫盘**：复用同一次扫描的文件快照，不会因为加了索引变慢或更烫。

## 2. 安装前准备

1. **已装 vc2~vc6 的：直接覆盖安装**，同一把证书、`versionCode` 更大，不用卸载，私有日志保留。
2. **装的是 2026-11-05 之前 `CN=Android Debug` 老包的**：先卸载，证书不同会报签名冲突。
3. 把 APK 传到手机，**注意别选 `delivery\archive\` 里的旧包**。
4. Flyme 需允许「安装未知应用」：设置 → 应用管理 → 特殊权限 → 安装未知应用 → 选文件管理器 / 浏览器 → 允许。
5. 首次打开授予「所有文件访问权」（必需）与「用量访问权」（可选）。
6. **Shizuku 不是本轮重点**：上一轮的绑定修复没有被改动，S 组只做快速复查；
   本轮重点是 **T（主题）/ F（页面一致）/ P（路径）/ L（大文件）** 四组。

## 4. 怎么把诊断报告发给我

1. App 内：**首页底部 / 关于页 →「测试诊断」**。
2. 可先在「补充说明」里写清复现步骤 / 期望 / 实际现象。
3. **本轮请按「只读扫描 → 清理 → 再生成报告」的顺序做一次**，并额外去 Shizuku 设置页点一次
   「一键诊断绑定」，把那段输出也一起发我 —— `bind_trace` 是定位第 5 条问题的关键。
4. 点「一键生成报告」→ 检查内容（已自动脱敏）→ 点「**分享报告**」或「**复制报告**」发给我。
5. 若仍有问题，请附**新拍的结果页截图**（要本轮的）。

**`report_format=4` 新增字段怎么读**：

| 字段 | 含义 |
|---|---|
| `last_bind_started` / `last_bind_reason` | 最近一次 bind 是「已发起」还是失败，失败原因原文 |
| `user_service_args` | 发给 Shizuku 的四个参数（tag / 后缀 / debug / version），缺项会直接体现 |
| `bind_trace:` | 绑定每一步：`pingBinder` → `checkSelfPermission` → `bindUserService` → `onServiceConnected` → `probe`；**FAIL 那行就是卡点** |
| `skipped` / `skip_reasons` | 防误删策略主动放弃的项，**不是失败** |
| `only_empty_dirs=true` | 本次只清了不占空间的空目录，所以释放 0 B 属正常 |
| `shizuku_installed` / `shizuku_ping_binder` | 区分「装了 Shizuku」与「服务真的在跑」 |

生成报告时会创建并立即删除一个 1 字节临时文件用于测试写入权限，不读取任何用户文件内容。

## 5. Shizuku 授权与绑定指引

> 你的报告显示服务已在运行、授权已给到，所以**不需要**再做「启动服务」这一步；
> 若哪天重启手机后服务掉了，回首页点「打开 Shizuku 启动服务」即可（重启后必须重启服务）。

1. 打开本 App → 首页「Shizuku 设置」。
2. 看「最近一次绑定结果」：`✓` 表示已发起并连上，`✗` 后面会写清原因。
3. 卡住时按顺序试：**重新绑定** → **刷新状态** → **一键诊断绑定**（把输出发我）。
4. 若报「绑定请求被拒绝」，常见原因：
   - Flyme「开发者选项」里的「**Flyme 支付保护**」需关闭；
   - Shizuku 的「已授权应用」列表里本 App 被撤销过授权；
   - Shizuku 本身在重启后未启动服务。
5. 深度清理必须在「已就绪」时才可进行；掉线立即中止，**基础清扫全程不依赖 Shizuku**。
